## 2. Corrections réalisées

### 2.1 Typecheck → exit code 0

Root cause confirmed precisely: `worker-configuration.d.ts` (generated by `wrangler types`, included project-wide by `tsconfig.json`) declares a global `interface Element` for Cloudflare's server-side `HTMLRewriter` API, which TypeScript merges with the DOM lib's own global `Element` — the merged `append()` signature no longer satisfies `ParentNode.append()`, breaking `fieldsRootFor`'s return type in `EditorToolbar.astro`.

**Fix:** replaced the `ParentNode` return type with a minimal local `FieldsRoot` interface exposing only `querySelectorAll` — the only member `fieldsRootFor`'s result was ever used for. No `as any`, no `@ts-ignore`, no change to `worker-configuration.d.ts` or `tsconfig.json`. Contact's Phase 2 fix and Travail's slot forms are untouched in behavior — verified by the full browser suite.

**Result:** `npm run typecheck` → **exit code 0**, 0 errors (confirmed by direct, unpiped exit-code capture, not inferred from output).

### 2.2 Deterministic test databases

`tests/dal/harness.ts`'s `resetTestDb(dirName)` had an implicit shared default directory (`.wrangler-test-dal/`), silently reused by 5 separate test files across 5 separate npm scripts (`db:test:dal`, `test:cms:work`, `test:cms:services`, `test:cms:testimonials`, `test:media`). Harmless under the current sequential CI, but nothing prevented two of them from being run concurrently by a developer — exactly the self-inflicted race that produced the flaky invariants results during Phase 3 closure.

**Fix:** `dirName` is now a **required** parameter — no default. Each of the 5 previously-implicit callers now names its own isolated directory (`.wrangler-test-media-actions`, `.wrangler-test-testimonials-endpoints`, `.wrangler-test-work-endpoints`, `.wrangler-test-services-endpoints`, `.wrangler-test-dal` made explicit for `tests/dal/dal.test.ts`). No test assertions changed — this is purely infrastructure.

**Verified**, not just asserted: ran `db:test:dal` and `test:media` genuinely concurrently (two backgrounded shell processes) — both passed cleanly (42/42, 18/18, both exit 0), confirming the exact collision class is now structurally impossible. CI stays sequential, unchanged. `test:browser`'s `--test-concurrency=1` (the `astro dev` single-daemon constraint) is untouched.

### 2.3 Accessibility

- **Focal point keyboard support** (was: click-only, unreachable by keyboard). `GallerySlot.astro`'s focal preview is now a real Tab stop (`role="group"`, `tabindex="0"`, `aria-describedby` pointing at the existing hint text). Arrow keys nudge by 2% (fine), Shift+arrow by 10% (coarse), clamped 0–100 — same `applyFocal()` helper the mouse click already used, so both paths stay in sync by construction. No new widget.
- **`aria-controls`** added on the "Modifier" toggle, pointing at the panel's own new `id` (one per slot, derived from `entry.position` — stable, unique, no client-side ID generation needed). Matches the pattern `EditorToolbar.astro`'s own mobile-menu toggle already used.
- **Contrast**: `.admin-topbar__email`/`.admin-mobile-nav__email` used `--color-text-discreet` (≈4.04:1) at `--text-small` — exactly the case `docs/ACCESSIBILITY.md` itself warns against. Switched to `--color-text-secondary` (≈7.1:1, AA-conformant).
- **Already correct, verified, left untouched**: `FlashMessage.astro`'s `role="status"`/`role="alert"` (success/error already announced), the layout picker's `role="radiogroup"` + `aria-label`, the native `<dialog>`'s built-in focus trapping.

All covered by an extended browser test (`tests/admin/gallery-slot-phase3.browser.test.ts`): keyboard focal-point nudge/coarse-nudge/clamping, and `aria-controls`/panel-id linkage.

### 2.4 Responsive

Real-browser audit (bounding-box inspection + screenshots) across all 5 editor pages (Accueil, Travail, Services, À propos, Contact), both toolbar states (collapsed/expanded), at 375px. **No real defects found**: zero horizontal overflow anywhere; the only "overlaps" detected were the fixed toolbar's *expanded* menu panel covering whatever's beneath it while deliberately open (same as any expanded overlay would) or a full-bleed image's oversized click target extending off-screen (harmless — the visible portion is still a large, easily tappable area). Confirmed the last Travail slot's controls are never permanently trapped behind the fixed toolbar even at full scroll (`#main`'s existing `padding-bottom: 3.5rem` reservation still holds). No code changes were needed here — the existing Phase 2 mobile-toolbar work already covers this correctly.

### 2.5 Minimal admin design system

New `src/styles/admin.css`: `.admin-btn`/`.admin-btn--primary`/`.admin-btn--small`/`.admin-btn--danger`, `.admin-badge`/`.admin-badge--warn` — built on the existing global tokens (`tokens.css`), no new variables invented. Imported only by `AdminLayout.astro` (the structured CMS: `/admin/work`, `/admin/media`, `/admin/services`, `/admin/testimonials`, dashboard) and `EditorToolbar.astro` (the Visual Editor chrome) — never `BaseLayout.astro`, so it never reaches the public bundle (verified: the built CSS chunk `EditorToolbar.*.css` is referenced by zero public static HTML files).

**Migrated** (per Boris's explicit priority — Visual Editor first, not a 17-file sweep): `EditorToolbar.astro`'s `.cms-toolbar__primary`/`.cms-toolbar__ghost*` and `GallerySlot.astro`'s `.gallery-slot__save-btn`/`.gallery-slot__ghost-btn*` — two independently-styled implementations of the identical "admin button" concept (different padding/min-height/border values, and `GallerySlot`'s buttons had no hover/focus feedback the toolbar's already had) — now one shared definition. Same for the "Masqué" status badge. **Not migrated** (left as-is, "progressively migratable"): the other 15 admin files (`WorkItemForm.astro`, `ServiceForm.astro`, media pages, etc.) — out of this phase's scope.

### 2.7 GalleryBlockFrame — shared admin/public geometry (validated, with a real bug caught in the process)

Extracted `src/components/GalleryBlockFrame.astro`: the composition geometry only (margins/widths/flex-splits per breakpoint for `full`/`centered`/`large`/`offset`/`duo`/`trio`), moved verbatim from `WorkGallery.astro`'s own CSS. Strictly presentational per the guardrail — no D1, no draft/publish, no admin concept, no media picker, no CMS buttons; content is injected entirely through named slots (`item-0`/`item-1`/`item-2`). `reveal` (scroll-fade-in) is opt-in, `false` by default — `WorkGallery.astro` passes it (preserving exact existing public behavior), `TravailGalleryEditor.astro` never does (an admin editing needs every slot visible immediately).

New shared type `GalleryBlockShape` in `gallery-blocks.ts` (the public-facing file — the natural home for "the closed set of composition blocks," per its own existing doc comment) is what both sides map onto: `WorkGallery.astro` passes its `GalleryBlock` objects directly (structural typing, extra image fields simply ignored); `TravailGalleryEditor.astro` maps its own `GallerySlotShape` (`work-gallery-layouts.ts`) onto the same vocabulary via one small `toBlockShape()` function.

**A real bug was found and fixed during this extraction's own verification, before it ever reached staging:** the first version used `slot={`item-${i}`}` (a template literal computed inside `.map()`) for the "trio" block. Astro's compiler resolves `slot="..."` names **statically** — a computed slot name is not supported and compiled cleanly (0 lint/typecheck errors) but crashed the SSR render at runtime (`ReferenceError: i is not defined`), truncating the response mid-stream specifically for the Story layout (the only one using `trio`). Caught by this extraction's own before/after verification process, not by any pre-existing test — none of the existing public test suites ever render the `.astro` templates through Astro's real compiler, only the pure data functions. **Fixed** by unrolling the trio branch into 3 static slot names (`item-0`/`item-1`/`item-2`), same content, no dynamic slot names anywhere in the codebase now.

**Guardrail verification (public side — zero visual change):**
- Automated geometry fingerprint (bounding boxes, margins, computed aspect-ratio) captured **before** and **after** the extraction, across both layouts that exercise every block type in real seeded data (Editorial: large+duo; Story: full+duo+trio) at 3 breakpoints (375/800/1440px) — **33/33 block/viewport combinations byte-identical**, before vs. after.
- New regression test `tests/public/gallery-block-frame.browser.test.ts` (3 tests, one per real layout: editorial/story/minimal) — asserts HTTP 200, a complete render (footer present — a truncated SSR crash never reaches it), at least one block rendered, and zero uncaught JS exceptions. This is the test that would have caught the trio bug immediately; it's now a permanent guard against the same class of regression.
- Full public test suite (81 tests) and full browser suite (19 tests, including the Travail admin editor cycling through all 3 layouts) — all green.

**Admin side (the actual goal — reduced divergence):** `TravailGalleryEditor.astro`'s own approximate `.travail-gallery-editor__block--*` CSS is gone, replaced by the same `GalleryBlockFrame` the public page uses. Visually confirmed via screenshot: the "Story" layout's `full` block now renders genuinely full-width in the admin editor, matching the public page's proportions, instead of the previous CSS approximation.
